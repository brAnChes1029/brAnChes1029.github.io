想得到一個 $n$，就必須花費 $0$ 到 $n-1$ 各一個。
可以從 $n$ 往 $0$ 數回來，若數字 $i$ 需要 $k$ 個，就把 $0$ 到 $i-1$ 的現有數量各減 $k$，然後答案加上 $k$。

Lego Wall

這題 QOJ 的子題好像切爛了，但測資本身沒問題。

寬度比較小

假設要拼一個高度為 $1$，寬度為 $i$ 的牆壁，那方法數應該是費氏數列第 $i$ 項 $fib_i$。
如果要拼一個高度為 $h$，寬度為 $i$ 且「不考慮牆壁有沒有斷掉」，方法數就是 $fib_i^h$ ( 可以用快速冪算 )。

令 $dp[i]$ 表示要拼出高度 $h$，寬度 $i$ 且不可以斷掉的牆壁，有幾種方法。
可以用扣的，$dp[i]=fib_i^h - \sum_{j=1}^{i-1} dp[j] \times fib_{i-j}^h$。

複雜度 $\mathcal{O}(w^2+w \log h)$。

高度比較低

考慮另一種 DP。

令 $dp[i][j]$ 代表拼出寬度 $i$，且有 $j$ 個寬度為 $2$ 的積木凸出到第 $i+1$ 行，有幾種方法。
這張圖表示 $dp[3][3]$ 的其中一種長相。

可以先初始化 $dp[1][j]=\binom{h}{j}$。

算 $dp[i][j]$ 的時候，可以枚舉所有 $h-k \geq j$，$dp[i][j]+=dp[i-1][k] \times \binom{h-k}{j}$，代表在 $h-k$ 個凹進去的地方選 $j$ 個放寬度為 $2$ 的積木。
最後的答案會是 $\sum_{j=1}{h-1} dp[w-1][j]$ ( 剩下洞可以用寬度 $1$ 的積木填補起來 )。
注意如果 $W=2$，答案要再加 $1$，因為有可能全部都是用寬度為 $2$ 的積木。

複雜度 $\mathcal{O}(wh^2)$。

full

寬度比較小的時候用方法一，高度比較低的時候用方法二，就可以過了。

Tourists

subtask 1 & 2 & 3

對於操作 t，用倍增 LCA 把人移到目標城市；對於操作 e，就 $\mathcal{O}(m)$ 看每個人是不是在這個城市，是的話就加值，這樣是 $\mathcal{O}(mq \log n)$。

full

如果有個人到城市 $c$ 時，城市 $c$ 的權重是 $e[c]=d_0$，接下來辦了很多活動 $d_1, d_2, d_3…$，最後權重變成 $e[c]= \sum{d_i}$，這個人的滿意度會變成 $\sum{d_i} - d_0$，所以只需要知道來的時候權重多少，和現在權重多少，就可以知道這段時間增加多少滿意度了。
可以使用「差分」做到這件事。

對所有人開一個懶標線段樹，並在每個 node 紀錄一個變數 $city$ 代表這個 node 底下所有人都在這個城市，如果大家所在城市不同則 $city=-1$；還要另外維護一個差分變數 $v$。

  • 對於操作 e，可以維護一個陣列 $e$ 紀錄每個城市當前權重，直接加值。
  • 對於操作 t，用線段樹遞迴下去，如果現在的 node 所有人都在 $city$ 這個城市，並且要移動到 $des$ 這個城市，就把 $v$ 加上 $e[city]-e[des]-LCA(city, des)$，然後把 $city$ 改成 $des$；若不是全部人都在同一個城市，就暴力遞迴下去。
  • 對於詢問 q，用線段樹遞迴求出他的父節點一路上的 $v$ 的總和 $x$，和這個人現在在的城市 $now$，答案就是 $x+e[now]$ ( 因為是差分，要加回去 )。

至於 t 操作為什麼均攤是好的，令現在有 $U$ 對的人編號相鄰但是在不同的城市，一次 t 的操作最多使 $U+=2$ ( 把一個連續區段的中間段的人移到別的地方 )。

總複雜度 $\mathcal{O}(n \log n + (m+q) \log m \log n)$，也可以用 $\mathcal{O}(1)$ 查詢距離把後面的 $\log n$ 壓掉。

Superpiece

full

考慮這些棋子從 $(0,0)$ 移動到 $(x,y)$ 所需要的步數 :

  • P : 如果 $y=0$ 且 $x>0$ 的話走 $x$ 步會到，否則走不到
  • Q : $2$ 步內一定會到
  • R : $2$ 步內一定會到
  • K : $max(|x|, |y|)$ 步
  • B : 若 $x+y$ 是 $2$ 的倍數就可以在 $2$ 步以內到，否則走不到
  • N : 我不會算欸

騎士的步數有以下的公式 ( Knight Metric ) :

$$dis=max( \lceil\frac{|x|}{2}\rceil, \lceil\frac{|y|}{2}\rceil, \lceil\frac{|x|+|y|}{3}\rceil )$$

如果 $dis$ 和 $|x|+|y|$ 奇偶性不同還要 $+1$，然後 $(1,0)$、$(2,2)$、$(1,1)$ 需要特判。

至於這是怎麼推出來的，可以參考 這個人畫的彩色的圖。

先判掉一步可達的情況 :

  1. 在 $x$ 或 $y$ 軸上且有 Q 或 R。
  2. 在 $x+y=0$ 或 $x-y=0$ 上且有 Q 或 B。
  3. 任何其他棋子走一步會到。

接下來如果有 Q 或 R 的話兩步可以到，先判掉。
最後剩下 P K N B，觀察到任何最小移動方法如果不是只使用一種棋子，就是先用某種棋子走一步之後改使用另一種棋子走完剩下的。

原因是 :

  1. 如果有 B，就用 P K N 任一種改變所在格子的奇偶性，B 就可以在兩步內跳到。
  2. 否則就是剩下 P K N，因為 P K 花兩步以上走到的地方 N 可以花更少 ( 或一樣 ) 的步數抵達，所以 P K 最多貢獻一步。

subtask 1

full

令 $small[i]$ 代表 $i$ 在原始的圖中可以連通的最小的點編號，現在依序由小到大加入點 $j$，想知道 $j$ 在原始圖中最小可以連通的點是誰。

複製的圖有一個性質是如果 $x$、$y$ 不連通，就會建一條邊使 $x$、$y$ 連通，所以可以利用這個性質做出一些圖，令 $idx[i]$ 代表編號 $i$ 的圖可以把 $1$ 到 $idx[i]$ 變成連通，這樣就可以對這些圖二分搜，找到 $j$ 在原始圖中最小可以連通的點是誰。
之後再把 $j$ 這個點跟 $1$ 到 $j-1$ 的圖連通起來，這樣之後要加進來的點也可以繼續二分搜。

最後如果 $small[i] \neq i$，就把這條邊加進答案。

詢問總數大概是嚴格小於 $\mathcal{O}(n \log n)$ 但會比 $1350$ 大一些，但如果控制好對那些版本的圖二分搜之類的話，其實跑不到到這麼多。

幫所有線分組，把旋轉後會長一樣的線分在同一組，這樣有 $7$ 組，每組 $4$ 條線。

考慮 DP ( 以下都是 0-base )，$dp[i]$ 代表第 $i$ 組的線來負責傳達「哪個方向在上面」 ( 共 $3$ 種畫法 )，$0$ 到 $i-1$ 組的線可以隨便傳 ( 最多總共可以傳 $2^{4i}$ )，$i+1$ 組之後的線都不可以傳方向的資訊 ( 總共可以傳 $4^{6-i}$，$4$ 是因為四條線共 $16$ 種要不要畫的方式，減掉 $4$ 個方向各有 $3$ 種可以表達方向的方式 )。

這樣有 $dp[i]=2^{4i} \times 3 \times 4^{6-i}$，$dp[0]+dp[1]+…+dp[6]=67104768$。

這樣要傳某數字 $n$ 時，就從 $dp[0]$ 開始看，若 $n$ 比 $dp[0]$ 大，就減掉 $dp[0]$，然後往後試 $dp[1]$…直到 $n<dp[i]$，那就以第 $i$ 組作為傳遞方向的組別，用上面的方法傳數字。

解密的時候從第 $6$ 組找回來，看從哪一組開始傳的線的樣子有方向的資訊，就知道上面那步選的 $i$ 是什麼了，接下來就是把圖轉回來然後解密。

實作是個大考驗，可能多用 bitmask 是不錯的選擇。

Bikes vs Cars

subtask 1 & 2

只要 $B+C \geq W$ 就可以成功建造道路 ( $B+C<W$ 多出來的路寬會使條件無法符合 )，可以在每個 $i$ 和 $i+1$ 建一條腳踏車道寬為 $B$ 的路和一條腳踏車道寬為 $W-C$ 的路。

full

對於每個 $b[i][j]$ 和 $c[i][j]$，必須滿足 $b[i][j]+c[i][j] \geq W$ 才可以蓋這兩條路，否則多出來的路寬會使條件無法符合。

看一下定義 ( 腳踏車道寬 $B$、汽車道寬 $C$ ) :

$$b[i][j]=\max_{\text{every path from } i \text{ to } j}\left( \min_{\text{every road on this path}}(B) \right)$$
$$c[i][j]=\max_{\text{every path from } i \text{ to } j}\left( \min_{\text{every road on this path}}( C) \right)$$

先篩選出可以蓋的路，然後對腳踏車道和汽車道的路分別做兩次最大生成樹 ( 對於一條路徑，能通過這條路徑的最瘦的車為這條路上最小的汽車道路寬度，所以從寬度最大的邊開始選 )，接下來把這兩個最大生成樹選擇的邊集合合併起來，檢查是否滿足題目條件 ( 使可以從 $i$ 走到 $j$ 的最胖的腳踏車寬度為 $b[i][j]$、最胖的汽車寬度為 $c[i][j]$、圖是連通的 )，檢查的方法可以跑一個像 Floyd-Warshall 的東西 :

實作的部分若覺得要分別處理腳踏車和汽車檢查很麻煩，可以令 $a[i][j]=W-c[i][j]$，定義就會變成 :

$$a[i][j]=\min_{\text{every path from } i \text{ to } j}\left( \max_{\text{every road on this path}}(B) \right)$$

把對 $c$ 蓋最大生成樹改成對 $a$ 蓋最小生成樹，最後就只要檢查腳踏車道寬度是否符合條件了。

$K=7$ ( $100$ 分 )

Bouquet

full

可以先想到一個直觀的 DP，令 $dp[i]$ 代表考慮第 $1$ 朵至第 $i$ 朵的花，並且一定要摘第 $i$ 朵花，這樣最多可以摘多少花。
轉移的部分可以 $\mathcal{O}(N)$ 枚舉每個 $j<i$，只要滿足 $j+r[j]<i$ 和 $j<i-l[i]$ 就可以轉移，總共是 $\mathcal{O}(N^2)$。

優化一下，用一個線段樹存目前一些 $j<i$ 的 $dp[j]$ 的值，對於每個 $i$，先把所有符合 $j+r[j]<i$ 的花加進線段樹，再對 $[1, i-l[i])$ query，就可以在 $\mathcal{O}(\log N)$ 轉移好了。

另解

如果你討厭線段樹 ( ? )，可以用一個陣列 $v[i]$ 存最小的 $j$ 滿足 $dp[j] \geq i$，因為 $v$ 陣列的元素會遞增，轉移的時候就可以二分搜了。

Team Coding

subtask 2 & 4

先說 subtask 4。
先對整個樹 DFS 一次，算 $cnt[lan][depth]$ 代表在 $depth$ 這個深度有多少人用 $lan$ 這個語言。

接下來 $\mathcal{O}(N)$ 枚舉每個點當 team leader，再對 team learder 的子樹 DFS 一次，算 $cnt2[depth]$ 代表這個深度總共有多少人，和 $cnt3[depth]$ 代表這個深度有多少人使用和 team leader 同一種語言，之後就可以看每個深度可以換掉多少人。
總複雜度 $\mathcal{O}(N^2)$。

對於 subtask 2，假設樹根的人使用 $0$ 號語言，那就只要計算 team leader 選擇使用 $1$ 號語言的情況了。

如果一個點 $i$ 和他的祖先 $p$ 都是使用 $1$ 號語言，那就不用計算以 $i$ 為 team leader 的狀況，因為選擇 $p$ 當 team leader 一定可以有比較多人。
因此可以用 subtask 4 的做法，因為每個計算的子樹都是獨立的，會均攤 $\mathcal{O}(N)$。

subtask 3

$\mathcal{O}(N)$ 枚舉每個點當 team leader，假設他使用的語言有 $C$ 個人使用。

接下來 $\mathcal{O}( C)$ 其他使用相同語言的人，如果在子樹內就留著，在外面就考慮可不可以換進來 ( 所以也要考慮子樹內每個深度有多少位子可以換，想知道子樹內部某深度有多少人，可以在 DFS 時先記錄每個點開始 DFS 和結束 DFS 的時間，若 $j$ 在 $i$ 的子樹內，會有 $tin[i]<=tin[j] \text{ and } tout[i]>=tout[j]$，可以用一個 vector<pair<int,int>> d[x] 存深度為 $x$ 的點的 $tin[j]$ 和 $j$，然後就可以用二分搜知道在 $i$ 的子樹內深度 $x$ 共有多少人 )。

總複雜度 $\mathcal{O}(NC \log N )$，這個子題說 $C_{max}=10$。

full

$\mathcal{O}(N)$ 枚舉每個點當 team leader，假設他使用的語言有 $C$ 個人使用。

  1. 如果 $C \leq \sqrt{N}$，那就用 subtask 3 的做法，可以 $\mathcal{O}(N \sqrt{N} \log N)$ 做完。
  2. 如果 $C > \sqrt{N}$，因為使用人數大於 $\sqrt{N}$ 人的語言不會超過 $\sqrt{N}$ 種，那就用 subtask 2 的作法，可以 $\mathcal{O}(N \sqrt{N})$ 做完。

令 $nxt[i]$ 代表沿著箭頭走 ( 從 $i$ 走到 $a[i]$ )，遇到的第一個 $j<i$ ( 先把 index 變成 1-based，如果沒有符合條件的 $j$，代表 $i$ 在這個環中是 index 最小的，就把 $nxt[i]$ 設為 $0$ )。
令 $pre[i]$ 代表逆著箭頭走，遇到的第一個 $j<i$ ( 如果沒有符合條件的 $j$，就把 $pre[i]$ 設為 $0$ )。

令 $B_0(i)$ 代表 $i$ 號房子一開始的雕像狀態。

  1. 先使 $B_1(i)=B_0(i) \oplus B_0(nxt[i])$，代表第 $i$ 號房子在第一輪結束時的雕像狀態，如果沒有 $nxt[i]$，那就是 $B_1(i)=B_0(i)$。

  2. 第二輪結束時使 $B_2(i)=B_0(a[i]) \oplus B_0(a[pre[i]])$。

    至於要怎麼做到 :

    • 對於 $nxt[i]=0$ 的 $i$，沿著這串跳回去

      沿路跟 $B_1(j)=B_0(j) \oplus B_0(nxt[j])$ xor 在一起，這一路上的東西最後會消掉只剩下最前面和最後面的 $B_0(a[i]) \oplus B_0(i)$，因為 $B_2(i)$ 一開始是 $B_1(i)=B_0(i)$，所以最後 $B_0(a[i]) \oplus B_0(i) \oplus B_0(i) = B_0(a[i])$。

    • 對於 $nxt[i] \neq 0$，沿著這串跳回去

      同樣利用消去，這段最後會剩下 $B_0(a[i]) \oplus B_0(nxt[i])$，將其跟 $B_2(i) = B_1(i) = B_0(i) \oplus B_0(nxt[i])$ xor 後，$B_2(i)$ 會變成 $B_0(i) \oplus B_0(a[i])$。

      接下來沿著反方向

      此時一定有 $j>i$，並且這一輪是反著走的，所以 $B_2(j)$ 已經是算好的 $B_0(a[j]) \oplus B_0(a[pre[j]])$，這一路上的東西消去剩下 $B_0(a[c[i]]) \oplus B_0(a[pre[i]])$。因為 $a[c[i]] = i$，所以結果就是 $B_0(i) \oplus B_0(a[pre[i]])$。

      兩者結合可以得到 $(B_0(i) \oplus B_0(a[i])) \oplus (B_0(i) \oplus B_0(a[pre[i]])) = B_0(a[i]) \oplus B_0(a[pre[i]])$。

  3. 目標是使 $B_3(i)=B_0(a[i])$。

    可以透過像是前綴和

    這一輪是從小走到大，所以 $pre[i]$ 一定會先遇到，根據遞迴關係 $B_3(i) = B_2(i) \oplus B_3(pre[pre[…]]) = B_0(a[i]) \oplus B_0(a[pre[i]]) \oplus B_3(pre[pre[…]])$ 會消掉只剩 $B_0(p[i])$。

subtask 1 & 2

觀察到最終一定可以剛好每一列都點一個橫的燈，或每一行都點一個直的燈。因為如果某列一個橫的燈都沒有，那一定是 $N$ 個直的燈。
可以隨便枚舉。

$Q=800$ ( $60$ 分 )

考慮對每一列二分搜出一個橫的燈泡。
在第 $i$ 列中點亮 $j=0 … x$ 的燈，如果這些燈裡面含有任何一個橫的燈，被點亮的格子數就會小於 $N \times (x+1)$。

但注意到如果 $x=0$，就沒辦法分出這顆燈泡到底是橫的還是直的，但可以透過二分搜前先「先排除這一列都是直的燈」來保證一定可以找到一個橫的燈，所以最後在 $j=0$ 和 $j=1$ 中一定存在至少一個橫的燈，可以比較點亮 $j=0$ 和 $j=2 … N-1$ 跟點亮 $j=1$ 和 $j=2 … N-1$，這兩種情況點亮總格數比較小的就會包含橫的燈。

先在第一列找到一個橫的燈之後，可以做個小優化，對於之後的第 $i$ 列，如果最後 $x=0$ 的情況發生，就直接拿第 $j=0$ 的燈跟第一列的確定是橫的燈一起點亮，就可以確定 $j=0$ 的燈的方向了，這樣可以省一次 query。

應該可以拿到 $50$ 到 $60$ 多分，看二分搜寫的好不好，我拿到了 $60.634444$ 分。

full

heuristic，使用一個很酷的方法。

  1. 先確定有沒有在每一列都找到一個橫的燈，或是每一行都找到一個直的燈，有的話就輸出解，然後結束。
  2. 維護一個集合，裡面存一些狀態 ( 用 bitset )，每個狀態代表每一個「目前觀察的燈」是直的還是橫的。如果這個集合不夠大了，就隨機抓還不知道的燈進來「目前觀察的燈」，因為這個燈有可能是直的或橫的，所以每抓一個燈進來集合大小就會變兩倍。
  3. 從「目前觀察的燈」隨機挑一些組合嘗試點亮，然後先算一下點亮這個組合的燈在最差情況下，最多可以刪掉多少的狀態。
  4. 拿剛剛嘗試的組合中，選在最差情況下可以刪掉最多狀態的組合，點亮看看 ( 問 grader )。
  5. 根據點亮的結果，把不合法的狀態刪掉。
  6. 找找看「目前觀察的燈」中，有沒有某些燈的方向確定了。也就是說，這個燈在所有狀態中都是直的，或都是橫的。
  7. 更新「目前觀察的燈」，如果某個燈的方向已經確定了、或同一列有橫的燈、或同一行有直的燈，那就不必在乎他的方向了，可以直接丟掉，也要從狀態集合裡面把這個燈刪掉。
  8. 重複。

這樣根據實驗結果會過，然後這題沒有官解 ( ? )。

Ovenmasters

full

首先每堆披薩第一個先加入答案，一個想法是可以從所有第二個的披薩和生氣的披薩這個集合裡面每次挑 index 最小的，然後看看能不能成功加進答案，之後再更新集合。
不過這樣是 $\mathcal{O}(n^2 \log n)$。

這邊有幾個觀察 :

  1. 先把所有桌子按照擺在最上面的披薩編號 $a[i]$ 由小到大排好，編號 $x$ 的披薩目標是放在第 $i$ 桌，必須先滿足 $a[i]<x<a[i+1]$ 這個條件，並且把 $x$ 號成功放上去之後桌上披薩的大小順序不會改變。
  2. 假設編號 $x$ 的披薩目標是放在 $i$ 桌，編號 $y$ 的披薩目標是放在 $j$ 桌 ( $i<j$ )，且這兩個披薩都有滿足上面的條件，一定有 $x<y$，而且一定是先放 $x$。
  3. 生氣的披薩在答案裡的順序一定是由小到大，因為如果在某一時間 $i$ 號披薩生氣地離開，所有編號比 $i$ 小的披薩也會生氣地離開。

接下來就可以用 priority_queue 存現在滿足條件的的披薩們各自目標是放到哪一桌上 ( 由桌子編號小到編號大 )，把披薩擺上去，然後更新滿足條件的披薩放進 priority_queue ( 如果剛剛在 $i$ 桌放了一個新披薩，$i$ 和 $i-1$ 號桌都要更新，因為 $a[i]$ 變大了，可能會使 $i-1$ 號桌的候選披薩符合條件 )。
至於生氣離開的披薩就看現在這個桌子的 $min=a[0]$ 是多少，就可以再用一個指針把所有 $x<a[0]$ 的生氣披薩放進答案。

以下用數學歸納法證明 ( 完蛋我不會數學 )。

對於 $N = 1$，Bianca 可以保證她的分數非負。

假設對於大小為 $1 \dots N-1$ 的餅乾堆皆成立。當在一個大小為 $N$、權重為 $W_0, W_1, \dots, W_{N-1}$ 的餅乾堆上玩遊戲時，Bianca 會：

  • Aurora 選擇 $X = 1$，那麼 Bianca 就選擇 $Y = 0$，並且吃掉總權重至少為 $W_0 + (W_2 + W_4 + \dots) \geq W_1 + W_3 + W_5 + \dots$ 的餅乾。
  • 不然 Bianca 就選擇 $Y = 1$，並且吃掉總權重至少為 $W_1 + (W_3 + W_5 + \dots)$ 的餅乾。

Aurora 可以總是選擇 $X = 0$ 確保 Bianca 吃掉的餅乾總權重最多為 $W_1 + W_3 + W_5 + \dots$。

subtask 2 & 4

考慮 DP。
令 $dp[i]$ 代表考慮 $i, i+1, … , N-1$ 塊餅乾，Bianca 可以獲得的最高權重。
可以對每個 $dp[i]$ 枚舉 $X$、$Y$ 來轉移，每次 query 都重新 DP 一次。

subtask 5 & 6

優化剛剛的 DP。
Aurora 會選一個 $X$，Bianca 必須選一個不一樣的 $Y$，然後從 $Y$ 轉移，所以 Aurora 可以把最好的轉移點擋掉，因此可以直接用 second max 轉移，這樣 DP 就變 $\mathcal{O}(n)$ 了。

full

令 $B[i]=\text{secondmax}_{i \le j}(W[j]+B[j+1])$。
令 $A[i]=\text{max}_{i \le j}(W[j]+B[j+1])$。
令 $D[i]=A[i]-B[i]$，$S[i]=A[i]+B[i]$。

現在要算 $S[i]$，因為 $S[i+1]=A[i+1]+B[i+1]$，而且現在多了新的轉移點 $W[i]+B[i+1]$，他一定比 $B[i+1]$ 大，如果他也比 $A[i+1]$ 大的話就會 $A[i]=W[i]+B[i+1]$，否則就會 $B[i]=W[i]+B[i+1]$，反正總有 $S[i]=A[i+1]+B[i+1]+W[i]=\sum_{j=i}^{N-1} W[j]$，所以 $A[0]+B[0]$ 會是全部餅乾的重量！

現在改算 $D[i]$，看上面的討論可以發現 $D[i]=|{D[i+1]-W[i]}|$，而且 $D[i]$ 的值域頂多到 $W_{max}$。

綜合上述，答案 $B[0]=\frac{\text{全部餅乾}-D[0]}{2}$。

subtask 3

使用像是線段樹那樣的想法。

第一輪，大家都在自己的 ID 上 write 1，然後按照 ID 0-1 2-3 4-5 6-7 這樣分組去看對方寫什麼，對方寫 $1$ 就可以知道這組共有 $2$ 人，看到 $0$ 代表這組只有一個人。
第二輪，01 23 45 67 各組決定出一個代表在 ID=0, 2, 4, 6 上 write 剛剛的總人數，然後按照 ID 01-23 45-67 這樣分組去看對方寫什麼，把對方寫的人數加進已知總人數。
第三輪，0123 4567 各組決定出一個代表在 ID=0, 4 上 write 剛剛的總人數，然後按照 ID 0123-4567 這樣分組去看對方寫什麼，把對方寫的人數加進已知總人數。
第四輪，最後的兩個人知道總人數，選一個代表把總人數 write 在 ID=0，之後其他人去 read。

各組要決定出一個代表才不會有多個人在同一個 ID 上 write，至於怎麼決定出一個代表，如果兩小組中都有人，就選編號小的。

這個想法可以推廣到 subtask 4，只能寫 0/1 的話，就把總人數用二進位多分幾次傳，可以拿到一些分數。

優化 1

上面說為了避免多人在同一地點 write，選擇讓編號小的作為代表負責 write，但這樣要花 $7$ 輪才可以傳一個 $N=100$ 這樣大的數字。

其實可以讓多人負責不同 bit，在同一輪 write。

要怎麼選出多人，可以維護每個人在現在組內的 ranking，合併左右兩邊的時候就把左邊的人 ranking 加上右邊的人數，然後讓 ranking 前 $7$ 大的人負責 $7$ 個 bit。

優化 2

這樣 merge 是一個樹狀的結構，但是在葉子的地方如果沒幾個人，就不需要用 $7$ bits 傳人數了，可以用少一點的 bit。
但是如果剛好遇上某一區人很多，又不能這樣節省了。

這裡可以用 random shuffle 把全部人初始分布位置變平均一點，random 的 seed 要是固定的 ( $N$ 個人的程式是分開執行的，但他們打亂的基準要是一樣的，才能成功打亂 )。
至於樹的哪一層要傳幾個 bit 就可能需要調整一下。

Cakes

full 1

$A[i]$ 代表 $i$ 號配料有多少個，$max$ 代表最多個的配料有多少個。

現在決定一個美味度 $d$，這個美味度最少會做出 $L=\lceil \frac{max}{d} \rceil$ 個蛋糕，最多也只能做出 $R=\sum_{i=0}^{N-1} \lfloor \frac{A[i]}{d} \rfloor$ 個蛋糕，至於在 $[L,R]$ 中的個數都是可以被做出來的。
接下來枚舉所有美味度 $d$，計算這個美味度最多可以做出多少個蛋糕 ( 也就是 $R$ )。可以枚舉 $\lfloor \frac{A[i]}{d} \rfloor=1, 2, 3, …$ 的蛋糕分別有幾個 ( 使用前綴和 )，就可以用調和級數和在 $\mathcal{O}(n \log_e n)$ 算完。

詢問想做 $x$ 塊蛋糕時，因為美味度越大可以做出來的最多的蛋糕數 $R$ 越少，所以選擇最小的美味度 $d=\lceil \frac{max}{x} \rceil$，接下來再檢查美味度 $d$ 可以做出最多的蛋糕數量是不是大於 $x$ 就好了。

full 2

官解。

也可以不用先算出每個美味度最多可以做出多少蛋糕，因為 $\lceil \frac{max}{x} \rceil$ 最多只有 $\sqrt{max}$ 種不一樣的值 ( 見這邊 )，所以可以算過的存起來，遇到新的就暴力算。

每個連通塊紀錄 $minL$、$minR$、$maxL$、$maxR$。
觀察到我要把區間 $[L,R]$ 和一個連通塊合併時，以下情況會無法合併 :

  2. $L>maxL \text{ and } R>maxR$

用一個 set 存連通塊，按照 $minL$ 由小到大排序，這裡有一個性質是 $minR$、$maxL$、$maxR$ 也都會分別遞增 ( 可以畫圖然後反證看看 )。

subtask 2 & $65$ 分

先抓前 $5$ 個人，詢問 $\binom{5}{3}$ 次然後把結果存起來，之後用 next_permutation 找到排列，就可以知道前 $5$ 個人的相對位置，然後用 set< pair<int,int> > 把位置和人的編號存起來。
選 $5$ 個人是因為選 $3$ 個或 $4$ 個人都沒辦法得知相對位置。

接下來對於所有未知位置的人，詢問他跟最前面兩個、最後面兩個的人距離多少，就可以推出他的位置，然後加進 set。

總詢問次數是 $2N$，可以拿到 $9+11+10+35=65$ 分。
