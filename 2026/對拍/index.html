發現我到現在還不會對拍，大燒雞了。

對拍就是在本地隨機生測資餵給 sol.cpp ( 找不到 bug 的假解 ) 跟 brute.cpp ( 在小測資會正確的暴力解 )，找到讓 sol.cpp 輸出錯的測資，能更有方向的找到 bug，不然就會盯著螢幕超久，好燒雞。

對拍的方式可以選擇寫一個程式或用編譯腳本。

生測資

舉例要生個隨機的序列 ( 但長度不要太長，太長 debug 很麻煩 ) :

其實 mt19937 的 seed 可以隨便給，就不用打一大串。

然後 uniform_int_distribution dis( l, r ) 是指生出來的數字會在 $[l, r]$ 內，如果要生出 long long 的話也可以用這個，絕對不是用什麼 uniform_long_long_distribution，根本沒這東西。

用 C++ 生測資還是比較麻煩，用 python 會比較方便，有空再學一下。

for Windows

寫個 check.cpp，它可以自動把生出來的測資 input.txt 餵給編譯好的 sol.exe 跟 brute.exe，然後自動比較兩邊答案 sol.out 跟 brute.out 是不是一樣。

操作步驟

  1. 先編譯
  2. 執行 check.exe
  3. 終端機會開始跑，停下來顯示 WA 的時候，打開 input.txt 就可以看到 WA 的測資，sol.cpp 的輸出會留在 sol.out，brute.cpp 的輸出會留在 brute.out，然後就可以 debug 了，好欸。
